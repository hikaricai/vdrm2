# 产品参考抓包：VSYNC、灰度与换行的 DCLK 时序

分析对象：[261024_250m_2s.dsl](../../../dsview/icnd2069/261024_250m_2s.dsl)。分析日期：2026-11-28。以下全部来自该包原始波形，不使用当前 RP2350 固件的时序代替测量。

**以 VSYNC 的 LE 拉高为起点：经过 3 个 DCLK 后 VSYNC 结束，经过 28 个 DCLK 后开始换行，首个灰度有效窗口位于偏移 732，首个灰度锁存在偏移 860 完成。扫描先启动，配置和灰度传输与扫描并行。**

共检查 **129 次 VSYNC、129 个完整灰度块、128 个完整帧间隔**。上述偏移全部一致；最后一帧的灰度已传完，但扫描尚未结束时采集停止。[原始统计](../../captures/experiments/20261128_产品参考时序/reference_timing.json)

## 1. 计数口径

本文的 `K` 表示：**从本帧 VSYNC 的 LE 上升沿起，到某事件之前，实际经过了多少个 DCLK 上升沿**。起点为 `K=0`，只数上升沿，不数下降沿。

- `LE ↑ K=0 → LE ↓ K=3`：VSYNC 高电平期间恰好包含 3 个 DCLK 上升沿。
- 首个灰度位采样点 `K=732`：该点之前已有 732 个上升沿，该位在本帧**第 733 个上升沿**采入。首块的 128 位占第 **733～860** 个上升沿。
- 事件处于同一整数 K 内，不代表它们在物理时间上完全同时。表中给出的是上升沿计数坐标，不是把所有事件对齐到 DCLK 的某个电平边界。
- 从 **VSYNC 结束**开始计数时，把本文所有 K 减去 **3**。

采样率为 250 MHz，536,870,912 点，真实时长 **2.147483648 s**。DCLK 主周期为 20 个采样点，即约 80 ns / 12.5 MHz；全包相邻上升沿间隔为 18～37 个采样点（72～148 ns）。因此不能简单用“时间 ÷ 80 ns”替代实际数 DCLK。

通道依据原[接线记录](../../../dsview/icnd2069/backgroud.md)，并用命令、RGB 和 ROW 波形核对：

| 通道 | 含义 |
|---|---|
| CH0 | DCLK |
| CH1 | LE / LAT |
| CH2、CH5、CH6 | R、G、B 串行数据 |
| CH3 | ROW，旧记录称 OE / 换行 |
| CH4、CH7 | RT5990 的未知引脚，不能直接命名为 DIN / LCK / BK，也不是 OUT0 / OUT1 |

## 2. 一帧开始时发生什么

下表在 **129 次帧头**中完全一致。LE 命令按高电平内 DCLK 上升沿数识别：3=VSYNC、11=EN_OP、14=PRE_ACT、5=WR_CFG、1=DATA_LATCH；定义见[编程指南第 5 页](../../../dsview/icnd2069/ICND2055-ICND2065-ICND2059-ICND2069-Programming-Guide-EN-2019-V4.2-Olympian.md#pdf-page-05)。

| 事件 | 开始 K | 结束 K | 说明 |
|---|---:|---:|---|
| VSYNC，LE 高 | 0 | 3 | 帧同步命令 |
| EN_OP，LE 高 | 15 | 26 | 每帧重新使能输出 |
| **第一个 ROW 高脉冲** | **28** | **40** | 首组首行，宽 12 DCLK |
| PRE_ACT，LE 高 | 29 | 43 | ROW 已启动，此时开始配置解锁流程 |
| WR_CFG `00=AA`，LE 高 | 175 | 180 | 解锁第 1 步 |
| WR_CFG `01=AA`，LE 高 | 311 | 316 | 解锁第 2 步 |
| WR_CFG 轮转项，LE 高 | 447 | 452 | 每帧写一项，地址/值见[寄存器汇总](../../../dsview/icnd2069/261024_250m_2s.registers.md) |
| WR_CFG `00=55`，LE 高 | 583 | 588 | 锁回第 1 步 |
| WR_CFG `01=55`，LE 高 | 719 | 724 | 锁回第 2 步 |
| **首个灰度块，第一个有效位采样** | **732** | — | 按首个锁存前 8×16 位回推 |
| **首个 DATA_LATCH，LE 高** | **859** | **860** | 最后一个数据位与锁存命令重叠 |

表中 WR_CFG 的“开始”指 **LE 拉高开始命令编码**，不是配置数据开始移入。五次配置的 128 位有效窗口分别从 **K=52、188、324、460、596** 的采样点开始，LE 只覆盖末尾 5 个 DCLK。

```text
同一帧，以 VSYNC 的 LE↑ 为 0；横向不按比例

LE 命令：VSYNC   EN_OP   PRE_ACT     5 次 WR_CFG                DATA_LATCH ...
K：      0→3    15→26    29→43       最后一次 719→724             859→860

ROW：                 ↑28──↓40   ↑109─↓113   ↑190─↓194  ... 持续换行 ...

灰度：                                                      第一个128位块
采样 K：                                                    732 ... 859
```

直接用于比较的间隔：

| 起止事件 | 实际 DCLK 数 |
|---|---:|
| VSYNC 结束 → EN_OP 开始 | 12 |
| EN_OP 结束 → 首个 ROW 开始 | 2 |
| VSYNC 结束 → 首个 ROW 开始 | **25** |
| VSYNC 结束 → 首个灰度有效位采样点之前 | **729** |
| VSYNC 结束 → 首个灰度锁存结束 | **857** |
| 最后一次 WR_CFG 结束 → 首个灰度有效位采样点之前 | 8 |

**灰度开始的证据边界：**首块为 OUT15，RGB 都是零；DCLK 又始终运行，因此数据线上没有一个可以唯一标记“开始发灰度”的跳变。`K=732` 是按 **8 颗级联、每颗 16 位，取首个 DATA_LATCH 前最后 128 个采样位**确定的有效窗口。首个锁存的 `859→860` 是直接观测事实；控制器内部何时进入“发送灰度”状态，波形不能唯一给出。

## 3. 灰度数据如何铺开

每帧 **640 次 DATA_LATCH = 40 行 × 16 个 OUT**。每次锁存前，RGB 各有 8 个 16 位级联字；沿用历史解码的 8 颗链长解释。原始位流逐字验证：每行 OUT15 为 `0000`，OUT14～OUT0 为 `02B8`，RGB 及各级联字一致。OUT15→OUT0 的含义来自[编程指南第 8 页](../../../dsview/icnd2069/ICND2055-ICND2065-ICND2059-ICND2069-Programming-Guide-EN-2019-V4.2-Olympian.md#pdf-page-08)，不代表已还原物理像素走线。

| 项目 | DCLK 特征 |
|---|---|
| 同一数据行内相邻锁存的间隔 | **136 = 128 位数据 + 8 个额外时钟** |
| 一行 OUT0 → 下一行 OUT15 的锁存间隔 | **137 = 128 位数据 + 9 个额外时钟** |
| 每帧两种间隔的次数 | 136：600 次；137：39 次 |
| 第一行 16 个 OUT 全部锁存完成 | K=2900 |
| 第二行 OUT15 锁存完成 | K=3037 |
| 最后一个灰度锁存结束 | **K=87803** |

第 `j` 次锁存从 0 开始编号，`j=0..639`，全包均符合：

```text
该块第一个有效位的采样 K = 732 + 136*j + floor(j/16)
DATA_LATCH 的 LE 拉高 K = 859 + 136*j + floor(j/16)
DATA_LATCH 的 LE 拉低 K = 860 + 136*j + floor(j/16)
```

这里的“灰度数据行”是写入 SRAM 的行，不等于此刻 ROW 正在扫描的行。首个灰度锁存完成时，本帧已经启动了 **11 次 ROW**；全部灰度写完时，已启动 **1084 次 ROW**，其余扫描继续运行。不能把这个重叠关系解释成“刚写入的字立即显示”；本包没有 OUT 输出或 SDO 回读证据。

## 4. 换行信号如何运行

每个完整帧均有 **2560 个 ROW 脉冲 = 40 扫 × 64 组**，与抓包写出的 `02h=27h`、`03h=3Fh` 一致。首个脉冲宽 **12 DCLK**，其余 **2559 个均宽 4 DCLK**。ROW 的上升沿表示开始新行，W12 标识首组首行，依据[编程指南第 11 页](../../../dsview/icnd2069/ICND2055-ICND2065-ICND2059-ICND2069-Programming-Guide-EN-2019-V4.2-Olympian.md#pdf-page-11)。

前几个换行上升沿的 K 为：

```text
28, 109, 190, 271, 352, 433, 514, 595, 676, 757, 838, 919,
999, 1081, 1161, 1243, 1323, 1405, 1485, 1566, ...
```

**ROW 周期以 81 DCLK 为主，但不能记成固定 81。** 每帧的 2559 个相邻间隔分布如下：

| ROW 上升沿间隔 | 每完整帧出现次数 |
|---:|---:|
| 80 DCLK | 141 |
| 81 DCLK | 1983 |
| 82 DCLK | 391 |
| 83 DCLK | 44 |

128 个完整帧的 **全部 2560 个 ROW 上升沿相对 K 序列逐项一致**；因此这里的 80～83 是重复的时序安排，不宜描述成随机帧间抖动。最后一个 ROW 在 **K=207645** 拉高、**K=207649** 拉低。此处只表示 ROW 信号的边沿，不表示最后一行 LED 的实际发光已结束。

CH4 每完整帧有 2560 次上升沿，CH7 有 64 次，分别具有行/组节奏；引脚身份未确认，本文不据此构造 RT5990 控制协议。

## 5. 下一次 VSYNC 何时到来

```text
K=0            28       732..860          87803               207649      下一帧
VSYNC↑         ROW开始  首块灰度→首锁存   全部灰度锁存完成    最后ROW↓    VSYNC↑
                └──────────────── ROW 持续扫描 ────────────────┘
                                                           └─380..465─┘
```

| 项目 | 实测结果 |
|---|---|
| 相邻 VSYNC 的 LE 上升沿间隔 | **208029～208114 DCLK** |
| 最后一个 ROW 下降沿 → 下一次 VSYNC 上升沿 | **380～465 DCLK** |
| 实际视频帧周期 | 平均 16.666698 ms，约 60 Hz |
| 实际帧周期范围 | 16.665136～16.668256 ms |

帧内灰度和 ROW 的 DCLK 坐标保持不变，帧总 DCLK 数的变化发生在最后 ROW 脉冲之后的等待区间。DCLK 在等待期间仍有上升沿。

抓包中的第一次 VSYNC 并不是设备上电的第一次 VSYNC；采集开始时 ROW 已在运行。第一次完整捕获的 VSYNC：LE 拉高位于采样点 **1,398,990**，即采集后 **5.595960 ms**；LE 拉低位于 **1,399,050**，即 **5.596200 ms**。本包没有 SOFT_RST / DIS_OP，不能据此推断产品上电时从不发送它们。
