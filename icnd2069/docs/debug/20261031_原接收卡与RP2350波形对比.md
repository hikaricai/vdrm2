# 原接收卡与 RP2350 波形对比

日期：2026-10-31。结论：**串行命令编码一致，但启动流程、配置重发策略、寄存器值、时钟连续性及扫描时序不完全一致。当前固件不是原接收卡波形的完整复现。**

**版本说明：本文表格描述 14:24 抓包对应的修改前固件。** 后续已按用户要求对齐配置轮转、R 链配置、12.5 MHz 连续 DCLK 和参考时序；保留 16 行/单颗适配。14:36 的一秒实测确认上述输入改变生效，OUT 仍恒低，详见 [最新实测记录](20261031_RP2350_DSView%E5%AE%9E%E6%B5%8B%E4%B8%8E%E8%B0%83%E8%AF%95%E8%AE%B0%E5%BD%95.md) 和 [当前运行说明](../../rp2350/README.md)。

此前“输入通过”只说明实际引脚波形与当前编码设计一致，且被检查的基本编码符合指南；不能扩大解释为与原接收卡全部行为一致，也不能据此排除固件/配置问题。

- 当前波形：[14:24:11 全屏 255 采集](../../captures/20261031/uniform255/20261031_uniform255_142411.dsl)，重新解析原始位平面，覆盖两个完整 VSYNC 间隔。
- RP2350 初始化：[初始化分析](../../captures/20261031/power_and_reconnect/20261031_after_reinit.v2.analysis.json)；当前 [协议源码](../../rp2350/src/protocol.rs) 的配置表仍与该基线一致，图案已改为全屏 255。
- [本轮结构化对比结果](../../captures/20261031/reference/20261031_reference_vs_rp2350.analysis.json)。旧短包全部 877 条命令的结束采样点、LE 时钟计数和 R 通道末尾 16 位，独立解码与已有 Rust 结果逐条一致。

**通道不可混淆：**旧包 CH1=LE、CH2=R；当前 CH1=SIN、CH2=LE。两者 CH3 都是换行信号。旧包 CH4/CH7 仅标注为 RT5990 的某个引脚，不能当成当前 CH4/CH5 的 OUT0/OUT1。

## 编码一致的部分

| 项目 | 对比结果 |
|---|---|
| 数据采样 | 都按 DCLK 上升沿，16 位 MSB 优先 |
| LE 命令长度 | DATA=1、VSYNC=3、WR_CFG=5、EN_OP=11、PRE_ACT=14，一致 |
| 锁存形式 | LE 覆盖数据末尾时钟，LE 下降结束命令，一致 |
| 配置字格式 | 高 8 位地址、低 8 位数值，一致 |
| 配置访问 | PRE_ACT → 00AA → 01AA → 写配置 → 0055 → 0155，一致 |
| 每行数据顺序 | 指南规定 OUT15→OUT0；旧包非均匀数据与该解释相符，当前源码按此顺序发送。当前全屏均匀数据本身不能证明物理列顺序 |
| 帧开头 | 都先 VSYNC、后 EN_OP |
| ROW 高电平编码 | 原始位流核对：两者每帧第一个 12 DCLK，其余 4 DCLK |
| 数据与扫描并行 | 两者都在 ROW 已开始后继续写灰度；不是先传完全部灰度才扫描 |

## 运行流程的实际差异

| 项目 | 原接收卡 | 当前 RP2350 |
|---|---|---|
| 启动 SOFT_RST / DIS_OP | 10.737 s 开机包中均未观察到 | 启动各发一次 |
| 配置更新 | 每帧重写一项，47 帧循环，约 0.7833 s | 启动集中写入一次，循环不重发 |
| 稳态命令 | VSYNC → EN → PRE_ACT → 5 次 WR_CFG → 灰度 | VSYNC → EN → 灰度 |
| 配置覆盖 | 00/01、02～23、70～74、F0～F5 | 00/01、02～23；其余未写 |
| DCLK | 主周期约 80 ns（12.5 MHz） | 主周期约 100 ns（10 MHz） |
| 时钟连续性 | 旧短包全部上升沿间隔 70～120 ns，未见微秒级停顿 | 当前包帧间上升沿间隔 8.28、9.30、10.30 µs |
| 扫描行数 | 40，02=27 | 16，02=0F |
| 每路级联 | 8 个 16 位字 | 1 个 16 位字 |
| 灰度锁存数/帧 | 640 | 256 |
| 连续灰度锁存间 DCLK | 136/137，即 128 位有效数据外还有 8/9 个时钟 | 主体 17，即 16 位数据外 1 个时钟；首字距 EN 结束为 33 个时钟 |
| ROW 数/帧 | 2560=40×64 | 1024=16×64 |
| ROW 周期 | 6.39～6.69 µs，80～83 DCLK，主要 81 | 15.99～16.01 µs，160 DCLK |
| VSYNC 结束至第一个 ROW | 2.08 µs，计得 25 个 DCLK 上升沿 | 3.80 µs，38 个 DCLK 上升沿 |
| EN 结束至第一个 ROW | 0.21 µs | 2.50 µs |
| 首个灰度锁存相对 VSYNC | 68.80 µs | 4.60 µs |
| 最后灰度锁存相对 VSYNC | 7045.28 µs | 438.10 µs |
| VSYNC 周期 | 16666.70 µs，约 60 Hz | 本包 16409.85 / 16410.89 µs，约 60.94 Hz |
| 图案 | 短包/250 MHz 包每行 OUT15=0，其余=02B8（696）；开机包全 0 | 当前所有像素=00FF（255） |

表中“原包未观察到”只限定现有采集窗口，不表示原控制器在任何情况下都不会发送该命令。40 扫与 16 扫、8 颗与 1 颗属于目标硬件差异，不能直接照搬数量；多出的 8/9 个前导时钟也不能无依据判为协议硬性要求。ROW 周期还与 PLL、消影参数有关，不能只改一个周期常量就假定匹配。

### 配置差异不仅有 PLL

以下以原接收卡 R 链与当前单路驱动比较；值均为十六进制。03=3F、07=08=20 相同，分别为 64 组和 K=32。

| 地址 | 原 R 链 | 当前 | 意义/边界 |
|---|---|---|---|
| 02 | 27 | 0F | 40 扫与 16 扫，硬件适配 |
| 04 / 05 / 06 | 04 / 0A / 01 | 02 / 08 / 02 | PLL，N 编码映射仍未确认 |
| 0C | 01 | 20 | 耦合优化 |
| 0E | 07 | 04 | 首行补偿 |
| 10 | C2 | 82 | 低灰优化等级 |
| 19 | 20 | 00 | 与 18 配合的补偿参数 |
| 1C | 72 | 40 | 电流增益 |
| 1D | 82 | CA | 指南未说明功能 |
| 1E | 41 | 42 | 消影参数 |
| 20 | 48 | 08 | 耦合增强开关存在差异 |
| 23 | 01 | 00 | 低灰偏移补偿 |

相对原 R 链，02～23 中共有 13 个地址不同，其中 02 是扫描数适配。原 G/B 链还有各自不同的补偿、电流参数，不能把 R 表直接认作 RGB 通用值。当前大量数值选自指南默认表，而不是全部取自接收卡实测。

原接收卡的 M=4 与约 12.5 MHz DCLK 组合，也不能按现有指南中的常规 PLL 约束机械解释；这进一步说明资料与实际设置的关系需要验证。当前没有 SDO 读回，比较的是发送值，不是芯片内部生效值。

## 行管与 OUT 的验证边界

旧短包 CH3 重新统计确认，每完整帧 1 个 W12、2559 个 W4。此前解码报告只覆盖 CLK/LE/RGB，本轮才补上原始 ROW 对比。

旧 CH4 每帧有 2560 次上升沿，高宽约 0.95～0.98 µs；CH7 每帧有 64 次上升沿。因具体 RT5990 引脚身份未确认，这些统计不能直接作为 LCK、BK 或 DIN 定义。

当前固件的 DIN/LCK/BK 是按先前 RT5960 思路及 RT5990 板级假设生成，当前六路也没有采集它们。因此，**尚未证明当前行管协议与原接收卡一致**。旧包没有明确的 ICND2069 OUT 测点，无法直接拿旧 CH4/CH7 对照新 OUT0/OUT1。

## 对目前故障的意义

1. **周期性重写配置是重要差异。** 原接收卡即使在芯片晚上电、错过早期配置后，后续仍有机会收到整套配置。当前固件只写一次，缺少这一恢复路径。这能解释两套系统对上电时序的敏感性为何可能不同，但不能单凭它解释本板全部现象。
2. **SOFT_RST/DIS_OP 是当前实现额外引入的启动行为。** 指南允许这些命令，但原开机包没有观察到，因此应该分离实验，不能把当前初始化当作原包已经验证过的流程。
3. **DCLK 帧间停顿是已证实的差异。** 对内部 PLL 的实际影响尚未测得；不能直接认定为根因，也不能在未验证前忽略。
4. **寄存器和行管仍在验证范围内。** 当前输入检查不能排除它们导致异常。下一轮应优先按可控改动逐项缩小这些差异，保留 16 行/单颗/全屏 255 的目标，避免同时更改整张配置和行时序而失去因果判断。

本轮只做只读对比与报告记录，没有修改、复位或烧录设备。
