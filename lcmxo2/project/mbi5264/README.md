# MBI5264：三组 RGB × 九路独立选择

原代码：`mbi5264/hdl/`。目标板原理图：
[LCMXO21200hc_SCH_Schematic3_2026-09-30.pdf](../LCMXO21200hc_SCH_Schematic3_2026-09-30.pdf)，
图纸芯片标注为 1200，但实板已确认为 **MachXO2-2000、TQFP144**。
当前构建目标为 `LCMXO2-2000HC-4TG144C`；HC、-4、C 沿用原配置，
仍需与完整芯片丝印对应。物理接线继续按上述图纸。

## 地址与时序

三组各有 R/G/B 和 SEL 输入，共用 `CLK`、`SEL_LAT`，输出共 81 路。
每组独立移入一个 4 位地址，同组 R/G/B 共用该地址：

| 地址 | 行为 |
| --- | --- |
| 0～8 | 分别选择第 1～9 路 |
| 9～15 | 广播至本组全部九路；MCU 初始化使用全 1，即地址 15 |

在 `CLK` 上升沿移入 SEL，低位移入、高位先发；在 `SEL_LAT` 下降沿锁存。
移位过程中保持上次锁存的选择。上电地址、移位寄存器和输出寄存器初始化为 0。

前八路每个 `CLK` 上升沿、下降沿采样当时的 decoded，并在该沿后输出，
边沿之间保持，没有额外半周期流水线延迟。
第九路直接组合输出。

双沿保持使用相反边沿的两个交叉反馈寄存器和 XOR，未使用原生 DDR：
上升沿更新 `encoded_pos = decoded ^ encoded_neg`，
下降沿更新 `encoded_neg = decoded ^ encoded_pos`，
输出为 `encoded_pos ^ encoded_neg`。每个边沿只有一组寄存器更新，
利用 `A ^ B ^ B = A` 输出当沿采样值；时钟暂停时保持。
反馈路径必须满足相邻边沿间的建立保持时间，输出有 FF 和 XOR 的传播延迟。

## MCU 传输长度无需改变

当前 `mbi5264/src/clocks.rs` 的 PIO 每 4 个系统周期输出一个 color 字，
`CLK` 周期为 8 个系统周期。8 个 color 字对应 4 个 `CLK` 上升沿，
SEL 在每两个 color 字中重复，刚好能传 4 位地址：

```text
color 序号：  0  1  2  3  4  5  6  7
当前 SEL：   0  0 a2 a2 a1 a1 a0 a0
四位 SEL：  a3 a3 a2 a2 a1 a1 a0 a0
```

因此不用增加 DMA 字数、改 PIO 指令或拉长 color 传输。
当前 MCU 数据生成仍有两个软件限制：

- `mbi5264-common/src/lib.rs` 的 `RGBH.h_idx` 只有 3 位，不能表示地址 8。
- `mbi5264/src/encoder.rs` 的地址表只有 8 项，首对 SEL 固定为 0。

若沿用该查表编码，4 位地址表需有 16 项，并在地址最高位为 1 时加入
`0x0000_0088`，其余三位掩码不变；地址来源也要能表示 0～8。
不要直接扩大 `RGBH.h_idx` 破坏现有 32 位图像格式，数据表示与图像生成需一起核对。
本工程完成 FPGA 侧扩展，现有 MCU 和图像文件尚未修改；旧编码器不能直接选第九路。
原初始化连续发送全 1 的过程可移入四个 1，仍能选择广播，无需加长。

## 编译与仿真

RTL 使用 SystemVerilog：入口为 `rtl/main.sv`，子模块为
`rtl/hc595.sv`、`rtl/decoder.sv`。使用 `logic`、`always_ff`、
`typedef` 和内部二维数组组织三组 RGB 输出，保留原有顶层管脚名。
综合脚本通过 Yosys `read_verilog -sv` 读取，仿真使用 `iverilog -g2012`。

从仓库根目录执行：

```sh
bash lcmxo2/project/mbi5264/build.sh
```

输出 `lcmxo2/project/mbi5264/build-open/led.bit`。
构建使用常规 nextpnr，直接生成 `led.bit`。
只综合可运行 `synth.sh`。脚本不会访问硬件。

仿真使用 Icarus Verilog：

```sh
brew install icarus-verilog
bash lcmxo2/project/mbi5264/sim.sh
bash lcmxo2/project/mbi5264/sim-synth.sh
```

RTL 及综合后网表仿真分别通过 41,187 次输出检查，
包含 8,257 个上升沿和 8,256 个下降沿，逐沿检查当前沿样本输出。
覆盖全部 16 个地址、512 种九位 RGB 输入组合、
三组独立选址、移位时保持旧地址、两种时钟电平下的地址锁存、
上下沿采样、当前值输出、边沿间保持、暂停时钟及第九路直通。
事件级监测未发现前八路在边沿间变化或在同一时钟沿重复跳变。
这是零延迟功能仿真，不包含器件和布线延迟，不能证明上板无毛刺。

本地 nextpnr 已启用 `1200;2000` 两种器件。新环境按
[工具链说明](../../OPEN_TOOLCHAIN.md) 安装。
当前 2000 数据库下，自动选择 DCC0 会出现专用时钟路由失败；
顶层显式使用 `X13/Y8/DCC2`（CLK）和 `X13/Y8/DCC3`（SEL_LAT）。
这两个位置属于本目标器件，换芯片时需要重新核对。

## 管脚

完整约束见 [board.lpf](board.lpf)。共 95 个端口，均使用唯一且有效的 TQFP144
IO 管脚，已逐脚核对封装迁移表的 LCMXO2-2000 列。
`R1[0]` 对应原理图 R11，`R1[8]` 对应 R19，其余组和颜色依此类推。
IO 使用 LVCMOS33，实际板卡对应 VCCIO 必须供 3.3 V。

| 组 | 输入 R/G/B 的 FPGA 脚号 | SEL 的 FPGA 脚号 |
| --- | --- | --- |
| 1 | 138 / 139 / 140 | SEL1：141 |
| 2 | 142 / 143 / 137 | SEL2：136 |
| 3 | 133 / 132 / 131 | SEL3：130 |

公共 `CLK` 为 58 脚，`SEL_LAT` 为 59 脚。上述数字均为 FPGA 封装脚号。

**原理图存在配置功能复用，尚未完成上板验证：**

| 原理图网络 | 封装脚号 | 配置功能 |
| --- | --- | --- |
| B2 | 137 | TDO |
| SEL2 | 136 | TDI |
| B3 | 131 | TCK |
| SEL3 | 130 | TMS |
| R32 | 110 | INITN |
| R33 | 109 | DONE |

上述 JTAG 管脚已与官方 pinout 交叉确认。官方文档确认，设置
`JTAG_PORT=DISABLE` 后，可用 **120 脚 JTAGENB：高电平启用 JTAG、低电平使用业务 IO**。
具体飞线、H24 接法、切换顺序和官方依据见 [JTAGENB 补救方案](JTAGENB.md)。

当前 `.bit` 烧录流程仍使用固定 FEABITS，保持 JTAG 启用，
尚未实现端口复用所需的非易失配置。布线成功不代表这些管脚已释放为用户 IO。
不能直接照搬旧 2000HC 流水灯板的 J2 接线。当前 2000HC 预期 IDCODE 为 `0x012bb043`。

## 构建验证记录

当前双沿当前值版本已按 `LCMXO2-2000HC-4TG144C` 重新完成综合、布局布线和
压缩码流生成，RTL 仿真通过 41,187 次输出检查。码流反解确认器件 ID 为
`0x012bb043`，`led.bit` 已更新为 2000 目标。
综合使用 168 个普通 FF、249 个 LUT4；nextpnr 打包后使用 168/2112 个 FF、
251/2112 个组合单元、2/8 个 DCCA。路由后 `main_clock` 报告 157.58 MHz，
通过 16.25 MHz 内部时序目标。
nextpnr 的 IO 总数 216 是芯片数据库中的资源数，不是 TQFP144 封装可用引脚数；
封装迁移表中 2000 的 TQFP144 有 112 个 IO 脚，当前分配 95 个，其中包含配置复用脚。
两个编码寄存器之间存在跨半周期反馈路径；上述检查不替代外部 IO 时序验证。
当前版本未上板。
